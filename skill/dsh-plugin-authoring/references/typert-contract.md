# Typert 契约（0.2.0-rc.2）

本文件覆盖 `./typert` Host 清单、strict codec、`./remote` Client 贡献与 gateway 边界校验。目标版本 DSH `0.2.0-rc.2`。

证据来源（三类，互相印证）：

1. 本机安装的 0.2.0-rc.2 runtime 源码：`@deepseek-ai/dsh-typert-loader`、`@deepseek-ai/dsh-api-gateway`（Host 与 Client 两半）。
2. 官方文档：[`/reference/subsystems/typert`](https://deepseek-harness.github.io/deepseek-harness/reference/subsystems/typert)、[`/reference/api-gateway`](https://deepseek-harness.github.io/deepseek-harness/reference/api-gateway)。
3. 版本化源码对照：`https://raw.githubusercontent.com/deepseek-ai/deepseek-harness/<tag>/packages/typert/protocol/src/types.ts`。

> Typert 生成产物由 `@deepseek-ai/dsh-typert-generator` 生成并标记 `do not edit`。本文件的代码片段是**形状参考**，不是可直接运行的实现，也不是生成器的替代品。之所以仍然记录这些形状：插件作者需要能读懂生成产物、能写契约测试、能在没有生成器的情况下判断一份产物是否过期。

## 1. strict codec：`schema` → `create()`

这是 0.1.x → 0.2 唯一会「一升级就装不上」的 Typert 破坏性改动。

```ts
// dsh-v0.1.1-rc.2
{ mode: 'strict'; typeSymbol: string; schema: TypertSchema }

// dsh-v0.2.0-rc.2
{
  mode: 'strict'
  typeSymbol: string
  /** Materialize and return the process-realm schema on first boundary use. */
  create: () => TypertSchema
  decode?: (value: unknown) => unknown
  encode?: (value: unknown, writeBytes: (bytes: Uint8Array, path: readonly (string | number)[]) => null) => unknown
}
```

`TypertSchema` 自身没变，仍是：

```ts
interface TypertSchema<Output = unknown> { parse(value: unknown): Output }
```

因此 `create()` 返回的对象**必须**有 `.parse`。gateway 的边界校验就是直接调用它：

```js
// dsh-api-gateway Host 半
function decode(codec, value, endpoint, field) {
  if (codec.mode === 'strict') {
    value = codec.create().parse(value)   // ← create() 在每次边界校验时被调用
    if (value === void 0) return value
  }
  assertJsonValue(value, new Set())
  return value
}
```

### 1.1 loader 的校验规则与报错原文

`dsh-typert-loader` 的 `requireStrictCodec()` 只做四件事：

```js
if (codec.mode !== 'strict')  throw `... must use a strict codec`
requireString(codec, 'typeSymbol')            // 非空字符串
['decode','encode'].forEach(m => { if (m !== undefined && typeof m !== 'function') throw `... ${m} must be a function` })
if (typeof codec.create !== 'function') throw `... has no create() factory`
```

对照排错：

| 你看到的报错 | 原因 |
| --- | --- |
| `typert-loader: <pkg> invocation "<id>" result codec has no create() factory` | 产物还是 0.1.x 形态，只有 `schema` |
| `typert-loader: <pkg> invocation "<id>" parameter codec must use a strict codec` | `mode` 拼错或被写成 `src-json` |
| `typert-loader: <pkg> TYPERT schema "<name>" has no create() factory` | `TYPERT.schemas[]` 的条目也要求 `create` |
| `typert-loader: <pkg> TYPERT manifest names package "..." — the manifest must be owned by the package that exports it` | `TYPERT.package` 与 `package.json.name` 不一致 |
| `typert-loader: <pkg> exports "./typert" but TYPERT.face is not "host"` | `face` 不是 `'host'` |

### 1.2 生成产物的真实形状

用惰性 memo 的箭头函数，而不是提前构造 schema。这样 schema 只在第一次边界使用时物化，避免模块求值期副作用：

```js
/* Generated by @deepseek-ai/dsh-typert-generator from FaceModel — do not edit. */
import { z } from 'zod'

let _pkg_service_method_result$schema$value
const _pkg_service_method_result$schema = () =>
  (_pkg_service_method_result$schema$value ??= z.union([z.literal(null), z.string()]))

export const TYPERT = {
  package: '@scope/my-plugin',
  face: 'host',
  schemas: [],
  invocations: [
    {
      id: '@scope/my-plugin#myService/ping',
      service: 'myService',
      namespace: 'myService',
      method: 'ping',
      invocation: { kind: 'direct' },
      parameters: [],
      result: {
        mode: 'strict',
        typeSymbol: '@scope/my-plugin#myService/ping:result',
        create: _pkg_service_method_result$schema,
      },
      sourceLocation: { file: 'packages/my-plugin/src/index.ts', line: 51, column: 9 },
    },
  ],
  model: { services: [/* ... */], events: [], objects: [] },
}
```

要点：

- `import { z } from 'zod'`；`zod` 属于**生成产物**的运行时依赖。
- `create` 是普通函数引用（可带 memo），不是 `schema` 的包装对象。
- `sourceLocation` 是生成期信息，允许省略；有则 `line`/`column` 必须是 ≥1 的整数。
- `schemas: []` 合法。

### 1.3 `typeSymbol` 的三种命名形态

从真实生成产物归纳：

```text
<pkg>#<service>/<method>:result          # 结果 codec
<pkg>#<service>/<method>:<paramName>     # 该方法的 JSON 参数 codec
<pkg>/types#<TypeName>                   # 引用共享类型
```

`typeSymbol` 在 Context/lookup provider 匹配时会被比较（provider 的 `wireTypeSymbol` 必须等于 codec 的 `typeSymbol`），所以它不只是文档字符串。

## 2. `./typert` Host 清单：loader 会校验的每个字段

`validateTypertManifest()` 逐字段强校验。下面列出**必填**与**可选**，避免写完才发现缺字段。

顶层：

| 字段 | 要求 |
| --- | --- |
| `package` | 必填，必须等于导出它的包的 `name` |
| `face` | 必填，严格为 `'host'` |
| `schemas` | 必填数组；元素是对象，含 `name`（非空字符串）与 `create`（函数） |
| `invocations` | 必填数组，逐项走 `requireInvocation()` |
| `model` | 必填对象，含 `services`、`events`、`objects` 三个**数组** |

`model.services[]`：

| 字段 | 要求 |
| --- | --- |
| `key` / `exportName` | 必填非空字符串 |
| `tags` | 必填数组（可为空） |
| `description` / `summary` / `jsDoc` | 可选，但给了就必须是字符串 |
| `members` | 必填数组；每个成员 `name`、`signature` 必填字符串，`kind` 必须是 `property`/`method`/`getter`/`setter`/`call`/`construct`/`index` 之一 |
| `types` | 必填数组；每项 `name`、`declaration` 必填字符串 |

`model.events[]`：`name`、`signature` 必填字符串，`mode` 可选字符串，`tags` 必填数组，`description`/`summary`/`jsDoc` 可选字符串。

`model.objects[]`：`name`、`exportName` 必填字符串，`members`、`types` 同 service。

> `TYPERT.model` 缺失或字段类型错误会让**整个 typert-loader 行激活失败**，于是该 profile 里所有插件的 RPC 路由一起不可用。这是「一个插件的 manifest 错误拖垮全局」的典型场景，所以第 3 节的契约测试很值得写。

`invocations[]`：

| 字段 | 要求 |
| --- | --- |
| `id` / `service` / `namespace` / `method` | 必填非空字符串 |
| `invocation` | 必填对象；`kind` 为 `'direct'` 或 `'context'`。`context` 时必须另有 `context`、`wire` 字符串，并带 strict codec |
| `parameters` | 必填数组。每项 `name`、`wire` 必填字符串；同一 invocation 内 `wire` 不得重复；`source` 必须是 `'json'` 或 `'lookup'`；`source: 'json'` 时不得声明 `lookup`；每项都要 strict codec |
| `result` | 必填 strict codec |
| `cancellation` | 可选；若给出，`parameter` 必须字面量为 `'signal'` |
| `scope` | 可选；仅 direct receiver 可声明。需要 `context`、`wire` 字符串，且该 `wire` 必须指向**唯一**的 lookup 参数，其 `lookup` 等于 `scope.context` |
| `sourceLocation` | 可选；`file` 字符串，`line`/`column` 为 ≥1 整数 |

`id` 与 wire endpoint 的分工：

- `invocation.id` 是 descriptor 的全局身份，常见形如 `package#service/method`。
- 实际 wire endpoint 是 `namespace/method`。
- **不要把带 `#` 的 id 当成 HTTP 路径或 RPC endpoint 发送。**

## 3. `./remote` Client 贡献

```js
/* Generated by @deepseek-ai/dsh-typert-generator from the Host FaceModel — do not edit. */
export const TYPERT_REMOTE = {
  package: '@scope/my-plugin',
  descriptors: [
    {
      id: '@scope/my-plugin#agentPresets/list',
      service: 'agentPresets',
      namespace: 'agentPresets',
      method: 'list',
      implementation: 'remoteExportList',        // 指向本模块里导出的实现名
      invocation: { kind: 'direct' },
      parameters: [],
      result: { mode: 'strict', typeSymbol: '...', create: _list_result$schema },
      sourceLocation: { file: '...', line: 171, column: 9 },
    },
    {
      id: '@scope/my-plugin#agentPresets/select',
      service: 'agentPresets',
      namespace: 'agentPresets',
      method: 'select',
      invocation: { kind: 'direct' },
      scope: { context: 'agent', wire: 'agentId' },   // ← 会话/agent 作用域投影
      parameters: [
        { name: 'agent', wire: 'agentId', source: 'lookup', lookup: 'agent', codec: { /* strict */ } },
        { name: 'agentPreset', wire: 'agentPreset', source: 'json', codec: { /* strict */ } },
      ],
      result: { mode: 'strict', typeSymbol: '...', create: _select_result$schema },
    },
  ],
}
export default TYPERT_REMOTE
```

与 Host 清单的差异：`descriptors` 取代 `invocations`，并有 `implementation` 字段。

Client Gateway 的硬约束（`installMethods` 路径）：

```js
if (codec.mode !== 'strict')
  throw new Error(`client api: generated Remote ${endpoint} field ${JSON.stringify(field)} has no strict codec`)
```

也就是说 **Client Remote 拒绝非 strict codec**。SRC 形态（`mode: 'src-json'`）只在 Host 从源码运行、没有 Typert 编译器插件时作为弱化回退出现；Client Remote 不会挂载缺少 strict codec 的 SRC descriptor。

可选钩子：`descriptor.result.decode` 存在时，Client 会用它做结果后处理（`value: descriptor.result.decode(result.value)`）。

### 3.1 挂载由 assembly 负责

```js
const unmount = await ctx.remote.$mount(TYPERT_REMOTE)
ctx.effect(() => unmount, 'my-plugin: remote contribution')

const result = await ctx.remote.myService.ping({ message: 'hello' })
if (!result.ok) throw result.error       // RemoteResult 错误分支
const value = result.value
```

`$mount` 通过 `ctx.effect` 登记，卸载时会按 descriptor 反向拆除各 namespace 方法。

#### 从 Agent 作用域调用

会话级 UI（输入栏、会话内面板）拿到的是 Agent 作用域 Context（`ctx.sessions.scope(sessionId)`）。它不是普通对象：创建它的 shell 插件只声明了自己的 inject 集合，所以对你自己 namespace 的属性读取会抛

```text
cannot get property "remote.myService" without inject
```

正确姿势是 inject 精确的服务 key（`remote.<namespace>`）；派生的 Context 仍带 Agent 标签，身份投影不变：

```js
// inject 回调不把值返回给调用方，用一个 promise 桥接
const binding = await new Promise((resolve, reject) => {
  agentCtx.inject(['remote.myService'], (c) => {
    Promise.resolve(c.remote.myService).then(resolve, reject)
  })
})
await binding.ping({ message: 'hello' })
```

- 调用方**永远不传 sessionId**：descriptor 的 `scope: { context: 'agent', wire: 'agentId' }` 由 Client Context adapter 填，Host 侧再用 `agent` lookup 换成精确 live 对象。把 id 从 UI 传进去，等于把授权判定权交给不可信输入。
- 拿不到 namespace 时（`$mount` 失败、shell 没加载网关）要 fail-closed **并给出原因**；不要回退成「默认第一个会话」，也不要静默假装未授权。
- `$mount` 通过 `ctx.effect` 登记，contribution 被真 Client Gateway 拒绝时失败会落在这个 effect 上；先用真 gateway 挂一次再谈运行时行为，模板见 [`templates/tests/client-remote-mount.test.mjs`](../templates/tests/client-remote-mount.test.mjs)。

## 4. 三层 envelope 不要混用

| 层 | 形状 | 失败语义 |
| --- | --- | --- |
| 生成 Client Remote 方法 | `RemoteResult<T>`：`{ ok: true, value }` / `{ ok: false, error }` | `result.error` |
| Host `typertGateway.invoke()` | 业务值本身 | 抛错 |
| Connection/API carrier（HTTP） | `{ ok, value }` / `{ ok, error }` | 取决于 carrier |

判断「业务结果本身是否带 `ok`/`value` 字段」不能靠字段名猜测 envelope；要按你所在层的 API 约定解包。business wrapper 在错误的层解包，最典型的表现就是「本来成功的调用被当成失败」或反过来。

## 5. 0.2 新增/改名的类型

| 0.1.x | 0.2.0-rc.2 |
| --- | --- |
| `RemoteFailure { code, message, details }` | `RemoteError<Code>` 判别联合 + 可合并扩展的 `RemoteErrorDetailsMap` / `RemoteErrorCode` |
| `TypertHostContextProvider` | `TypertHostContextAdapter` |
| `TypertClientContextBinder` | `TypertClientContextAdapter`（改为双向：`identity(ctx)` + `resolve(id)`） |
| — | `TypertClientRemote.$dispatch(...)` 移除；改用 `$on<Event>(event, listener)` |
| — | `descriptor.mode?: 'stream'`、`descriptor.uplink?: { codec }`、`RemoteStream`/`RemoteStreamHandle`、`ctx.invocation` |

通用 carrier code 固定声明为：`gateway/bad-request`（带 `issues`）、`gateway/cancelled`、`gateway/internal`。其余 code 由各包通过 declaration merging 扩展。

## 6. 命名与绑定

- Host Service 优先继承 `TypertRemoteService`（`constructor(ctx) { super(ctx, serviceKey) }`），或使用 `bindTypertRemote(this, serviceKey)`。
- 不要同时再 provide 另一个同 key 的实例，也不要发明第二套 key；生成 descriptor 会按 `service` 字段解析。
- `@Remote` / `@RemoteScope(key)` 装饰器来自 `@deepseek-ai/dsh-typert-protocol`。没有标记的方法不会进入生成类型，也不会进入运行时。
- 严格分析要求 Remote 方法是 **public、非 static、具体实例方法、非泛型**，参数必须是**具名、必填、简单标识符**：不支持解构、默认值、rest 或可选参数。
- 复杂 Host 对象要配 `TypertLookupMap` declaration merging 和 `ctx.typert.lookups` 上的运行时 provider（例如 `agent` 参数映射到 wire 字段 `agentId`）。
- 取消：Host 参数表的最后一个参数为 `signal: AbortSignal`，descriptor 记录为 `cancellation.parameter === 'signal'`，signal 带外传输、**不进入 `args`**。

## 7. 契约测试模板

手写或生成产物过期是最难在运行时定位的问题。下面这段测试只需几秒，能在 CI 里挡住它：

```js
import assert from 'node:assert/strict'
import { TYPERT } from '../lib/typert.host.js'

assert.equal(TYPERT.face, 'host')
assert.ok(Array.isArray(TYPERT.invocations) && TYPERT.invocations.length > 0)

const strictCodecs = []
for (const invocation of TYPERT.invocations) {
  for (const parameter of invocation.parameters ?? []) strictCodecs.push(parameter.codec)
  strictCodecs.push(invocation.result)
}

for (const codec of strictCodecs) {
  assert.equal(codec.mode, 'strict', 'every codec must be strict')
  assert.equal(typeof codec.typeSymbol, 'string')
  assert.equal(typeof codec.create, 'function', 'strict codec needs a create() factory')
  assert.equal(codec.schema, undefined, 'the 0.1.x schema field must be gone')
  const schema = codec.create()
  assert.equal(typeof schema.parse, 'function', 'create() must return a schema with parse()')
}

// 回归护栏：旧形态必须被拒绝
const legacy = { mode: 'strict', typeSymbol: 'x', schema: { parse: (v) => v } }
assert.equal(typeof legacy.create, 'undefined')
```

再补一条 assembly 级断言：`./remote` 的每个 descriptor 也要有 `implementation` 字符串和 strict codecs。若你的包有 package-level 契约测试（例如校验 `TYPERT.invocations.length` 与方法名清单），把上面的循环加进去即可，无需新增测试文件。

## 8. 排障顺序

1. **行没激活** → 先看 loader 的报错原文，按 1.1 的表定位是 `create`、`mode`、`package` 还是 `face`。
2. **行激活了但调用报 `gateway/input-invalid`** → `create().parse()` 拒绝了入参。检查 schema 与 Host 侧真实类型是否一致，而不是去放宽 `mode`。
3. **调用报 `gateway/provider-mismatch`** → Context/lookup provider 的 `wireTypeSymbol` 与 codec 的 `typeSymbol` 不一致。
4. **Client 端方法不存在** → 检查 `./remote` 是否被 assembly `$mount`，以及 codec 是否 strict。
5. **改了源码但行为没变** → 生成产物是构建结果；确认 `pnpm run build`（或等价的生成步骤）真的跑过，并确认 tarball 里带的是新产物。
